# Поиск фамилии в дореволюционном документе

Конвейер под сканы в Vivaldi (`vivaldi.dspl.ru` и другие установки этой
библиотечной системы). Отлажен на «Приказах по войску Донскому» за 1897 г.,
714 страниц: <https://vivaldi.dspl.ru/bv0000407/view/>

## Как пользоваться

Всё сразу:

```bash
python3 run.py https://vivaldi.dspl.ru/bv0000387 --find Кармазинъ Могучевъ
```

Или по шагам:

```bash
python3 fetch.py https://vivaldi.dspl.ru/bv0000407      # ~520 МБ, ~15 мин
python3 ocr_pages.py bv0000407                          # ~2 мин на 8 потоках
python3 find.py bv0000407 Кармазинъ
python3 find.py bv0000407 --history                     # что уже искали
python3 crop.py bv0000407 494 Могучевъ --line 260       # вырезать место находки
```

Оба первых шага возобновляемые: повторный запуск дочитывает недостающее.

## Раскладка

Документ опознаётся по последнему сегменту URL и живёт в папке этого имени:

```
bv0000407/
    meta.json        заголовок, URL, число страниц, dpi
    scans/           pNNNN.jpg
    ocr/             pNNNN.txt
    searches.jsonl   журнал поисков
```

Заголовок берётся из атрибута `data-title` у `<app-root>` во вьюере —
там чистое название, тогда как в `<title>` приклеены имя библиотеки и
слово Vivaldi.

## Журнал поисков

Каждый вызов `find.py` дописывает строку в `searches.jsonl` документа:
дата, фамилия, её основа, порог, название и URL документа, сколько
найдено и на каких страницах. Формат JSONL выбран ради дописывания:
оборванный на середине процесс не портит накопленное.

После проверки находок глазами итог фиксируется явно — сырое число
кандидатов обманчиво, и через месяц «найдено 5» читается как «фамилия
есть в документе»:

```bash
python3 find.py bv0000407 Кармазинъ --verdict "НЕ НАЙДЕНА. Все 5 — 'Кармалинъ' и имя 'Харлампію'."
```

`journal.html` в корне — сводка по **всем** документам сразу: сколько
их, сколько поисков, какие фамилии проверены и с каким итогом. С полем
фильтра (главный вопрос к такому журналу — «я это уже искал?») и
ссылками с номеров страниц прямо в онлайн-вьюер. Пересобирается сам
при каждом поиске, так что руками его трогать не нужно.

Таблица каждого документа свёрнута: на виду остаётся ответ по каждой
фамилии — найдена, не найдена, не проверена, — а даты, число кандидатов,
страницы и текст вердикта разворачиваются по клику. Вердикты длинные, и
при развёрнутых таблицах главный вопрос тонет в подробностях проверки.
Фильтр раскрывает совпадения сам и возвращает всё как было, когда поле
опустеет.

HTML здесь — представление, а не второе хранилище. Источник истины
остаётся в `<документ>/searches.jsonl`: дописывание строки переживает
обрыв процесса, а перезапись сводного файла — нет.

```
$ python3 find.py bv0000407 --history
[Приказы по войску Донскому]: за 1897 год
https://vivaldi.dspl.ru/bv0000407   страниц: 714

дата              фамилия           найдено  страницы
2026-09-01 18:20  Кармазинъ            3 (2 точн.)  118, 402, 511
```

## Устройство

| Файл | Что делает |
|---|---|
| `fetch.py` | Скачивание страниц через API вьюера |
| `ocr_pages.py` | Пакетный Tesseract, параллельно по ядрам |
| `find.py` | Поиск + склейка переносов через границу страниц |
| `docstore.py` | Раскладка по документам, метаданные, журнал поисков |
| `crop.py` | Вырезание найденного слова из скана для проверки глазами |
| `journal.py` | Сводный `journal.html` по всем документам |
| `run.py` | Весь конвейер по документу одной командой |
| `icon.py` | Иконка журнала (ять), `favicon.ico` |
| `prune.py` | Чистка сканов: оставить нужные, остальные выбросить |
| `quality.py` | Надёжность распознавания постранично |
| `rescue.py` | Перечитывание ненадёжных страниц полосами |
| `prep.py` | Бинаризация полутоновых сканов, третий слой прочтения |
| `surnamefind/normalize.py` | Дореформенная орфография, латинские глифы-двойники |
| `surnamefind/match.py` | Расстояние с учётом ошибок OCR |
| `surnamefind/search.py` | Токенизация со смещениями, основы фамилий |
| `eval.py` | Метрика: сколько фамилий страницы найдено |
| `tests.py` | 17 кейсов на матчер |

## API вьюера Vivaldi

Найдено в `/Scripts/document/dist/main.js`, объект `RouteConstants`.
База — атрибут `data-url` у `<app-root>`.

```
/page/sizes              число страниц и их размеры
/page/{n}/image/{dpi}    JPEG целой страницы; dpi произвольный, тайлов нет
/search/{query}          полнотекстовый поиск — для этого документа пуст
```

Авторизация не нужна. `data-downloadallowed="False"` ограничивает только
кнопку «скачать» во вьюере, постраничная отдача открыта.

**Соединение изредка повисает намертво, и таймаута `urlopen` от этого мало.**
На bv0000391 прогон простоял 16 минут на стр. 313, пока `curl` брал ту же
страницу за две секунды: процесс сидел в SSL-чтении заголовков ответа.
Причина в том, что `timeout=` ограничивает *одну операцию с сокетом*, а не
запрос целиком, — сервер, отдающий по байту раз в минуту, укладывается в
него бесконечно. Повторы не спасают: до них дело не доходит. Поэтому
`fetch.get` ставит на попытку жёсткий потолок через `SIGALRM`
(`fetch.Stalled` наследует `OSError` и попадает в общий разбор ошибок,
то есть выглядит как обычный обрыв и приводит к обычному повтору).
Сигналы ставятся только из главного потока, так что вызовы `ensure_page`
изнутри пулов (`prep.py`, `crop.py`) остаются на голом таймауте сокета.

## Что выяснилось на этом материале

- **OCR-слоя у библиотеки нет** — `/search/` возвращает `[]` на любое слово,
  распознавать приходится самим.
- **Сканы уже бинаризованы** (87% пикселей — чистые 0 или 255). Поэтому
  DPI выше 400 ничего не даёт: 150 и 600 dpi показывают тот же результат.
- **Водяной знак не мешает** — он тонкий контурный, Tesseract его игнорирует.
  Вычищать не потребовалось.
- **Модели `rus_old` в официальном tessdata не существует.** Есть `orus`
  из проекта iskra_ocr (дообучена на «Искре» 1900–1905). На нашем материале
  она чинит одни фамилии и ломает другие — итог тот же, `rus` достаточно.
- **`--psm 6` стабильно лучше `--psm 4`** на этой вёрстке.

## Точность

Стенд `eval.py`: 18 фамилий, вычитанных глазами со стр. 20.
Метрика — сколько из них находит матчер, а не CER: распознавание
калечит цифры и предлоги, это неважно, пока фамилии опознаваемы.

```
rus --psm 6 @400dpi     17/18
```

Единственный промах — `Сагацкій`, прочитанный как `Сагацый`.

## Решения в матчере

**Сравнение с началом слова, хвост до 5 букв бесплатен.** Так падежные
формы (`Кузнецову`, `Кузнецовымъ`, `Ивановскаго`) ловятся одним правилом
вместо словаря окончаний.

**Ошибка в последних 3 буквах штрафуется вдвое.** В русских фамилиях
идентичность несёт хвост: `-овъ` и `-инъ` — разные семьи, `кузнецъ` —
вообще ремесло. Без этого правила оба давали ложные срабатывания.

**Схлопнутая удвоенная буква стоит дёшево** (`Гурѣевъ` → `Гуревъ`):
два одинаковых глифа подряд OCR сливает регулярно, это не признак
другого слова.

**Дореформенные литеры в запросе помечаются как ненадёжные.** Если вы
пишете `Кирѣевъ`, а не `Киреев`, матчер знает, что позиция ятя может быть
испорчена как угодно, и не штрафует её полностью — при этом остальные
буквы сравниваются строго. Современное написание тоже работает, но хуже.

## Сканы — это кэш, а не данные

573 МБ сканов против 2.9 МБ распознанного текста. Держать их все ради
страниц, на которые больше никто не посмотрит, незачем — но и удалять
«всё, кроме найденного» нельзя: следующая фамилия даст кандидатов на
страницах, о которых сегодня ничего не известно, а проверять кандидата
без скана невозможно. Из пяти кандидатов на `Кармазинъ` все пять
оказались посторонними, и решил вопрос только скан.

Поэтому вместо спора о критерии сканы переведены в разряд кэша:
`fetch.ensure_page` молча дотягивает выброшенную страницу, когда она
понадобилась. `crop.py` этим пользуется, так что чистить можно смело.

```bash
python3 prune.py bv0000407           # предпросмотр
python3 prune.py bv0000407 --apply   # удалить
python3 fetch.py <url> --pages 179,494,500-505   # дотянуть выборочно
```

Что остаётся: страницы со **всеми** когда-либо залогированными
кандидатами (не только подтверждёнными — отсеявшийся кандидат тоже
могут захотеть перепроверить), страницы из вердиктов и вырезки в
`crops/`. Подтверждённые находки вырезаются **до** удаления: вырезка
крошечная и переживёт даже исчезновение документа из библиотеки.

Чистка откажется работать, если не все страницы распознаны: иначе она
уничтожит текст, которого ещё нет.

## Случай, который сломал первую версию

Фамилия `Могучевъ` в bv0000386 (стр. 208, приказ № 114) была пропущена,
и — что хуже — отрицательный ответ подавался как проверенный. Разбор
причины изменил конвейер сильнее всего остального.

Сочетание трёх вещей: **курсив**, **перенос через строку** и **узкая
колонка таблицы**. Tesseract прочёл `Могу-` как `Л/огу-`, а `чевъ` — как
`4:65`, приняв за цифры соседней колонки. Не помогли ни пять режимов
сегментации, ни вторая модель, ни кириллический фильтр, ни обрезка
числовых колонок. При увеличении выяснилась настоящая причина: **в
оттиске не пропечаталась буква «е»**, на бумаге стоит `ч‧въ`. Чернил нет
— восстанавливать нечего. Человек читает это слово только по `Могу-`
строкой выше.

Отсюда три изменения:

**Поиск по половинкам.** Если строка кончается переносом, первая
половина проверяется как начало фамилии — независимо от того, во что
превратилась вторая. `Могу` совпадает с основой `могучев` без штрафа.
Правило требует прописной буквы: иначе оно тонет в `могу-щихъ` и
`получе-нія` (реальный ложный след — bv0000407 стр. 654).

**Второй проход полосами** (`rescue.py`). Страница, нарезанная на
горизонтальные полосы внахлёст, читается заметно лучше целой: соседние
строки перестают влиять друг на друга. На стр. 208 это дало `Могу-` с
правильной буквой `М`. Дорого, поэтому применяется только к ненадёжным
страницам.

**Замер надёжности** (`quality.py`) по средней уверенности Tesseract.
Таблицы с курсивом дают 45–55, обычный текст 65–80. В bv0000386 ниже
порога оказались **126 страниц из 441 (29%)** — то есть прежний вердикт
«не найдена» покрывал в лучшем случае 71% документа, а звучал
окончательно. Теперь доля читаемого выводится в журнале, а ненадёжные
страницы называются поимённо.

```bash
python3 quality.py bv0000386     # измерить, записать quality.json
python3 rescue.py bv0000386      # перечитать ненадёжные полосами
```

`find.py` ищет и по обычному тексту, и по прочтению полосами: то, что
развалилось в одном, часто цело в другом. Половинчатые совпадения
помечены `½` — по опыту они чаще настоящие, чем шум.

## Три слоя прочтения

Одна страница может быть распознана несколькими способами, и `find.py`
ищет по всем сразу: то, что развалилось в одном прочтении, часто цело
в другом.

| Слой | Чем берёт |
|---|---|
| `ocr/` | обычный проход, вся книга |
| `ocr_bands/` | полосами внахлёст — спасает узкие колонки таблиц |
| `ocr_prep/` | по бинаризованному скану — снимает просвет оборота |

Третий слой понадобился на bv0000390 (1880 г.). Том оказался
**смешанным**: большинство страниц библиотека бинаризовала, но 62 — это
серые полутоновые снимки тонкой бумаги, сквозь которую просвечивает
оборот, и Tesseract читает два текста разом. Просвет светлее чернил,
поэтому порог по перцентилю гистограммы снимает его начисто; отдача
фамилий на пробной странице выросла с 2 из 8 до 4 из 8.

`prep.py` сам определяет, нужна ли обработка (доля чистых 0/255 в
гистограмме), и на уже бинарных томах не делает ничего.

Что **не** сработало на этом материале и проверено замером: больший dpi
(400→800 не даёт ничего на плохих страницах), растяжение контраста,
локальная адаптивная бинаризация, морфологическое размыкание (портит
сильно: 7 фамилий из 11 против 2 из 11).

## Осторожно с метрикой надёжности

На bv0000390 средняя уверенность 52 и «читаемо 24%», но это **сильно
занижено**. У 478 страниц тома просвет оборота уже впечатан в чёрное
самой библиотекой — убрать его нельзя, он плодит мусорные токены и
топит среднюю уверенность. При этом настоящий текст читается: замер
отдачи фамилий на двух таких страницах дал 7 из 11 и 5 из 6.

Вывод: уверенность Tesseract — годный указатель на проблемные страницы,
но не мера пригодности. Решает отдача фамилий, а её надо мерить вручную
на выборке.

## Ограничения

- Слово, разорванное пробелом внутри строки (`Кузнс цовъ`), не ловится.
  Лечится по координатам боксов Tesseract, не по тексту.
- Курсив распознаётся заметно хуже прямого набора.
- **Курсив распознаётся плохо, и это не мелочь**: в приказах курсивом
  набирают именно фамилию того, о ком приказ. `Могучевъ` на стр. 494
  прочитался как `Мотучевь` — матчер его вытянул, но с искажением.
- **Отрицательный результат слабее положительного.** «Найдена» проверяется
  по скану и потому надёжна. «Не найдена» верна лишь настолько, насколько
  читаем текст, поэтому смотрите долю читаемого в журнале и не считайте
  ноль кандидатов доказательством отсутствия.
- `crop.py` делает независимый проход Tesseract в режиме TSV: тот режет
  текст на слова иначе, чем построчная выдача, поэтому изредка слово,
  найденное поиском, у него не находится (стр. 485). Тогда смотрите
  страницу целиком.
- Проверять находку глазами обязательно. Из пяти кандидатов на
  `Кармазинъ` все пять оказались посторонними словами.
- Восстановление выброшенных сканов зависит от того, что документ
  остаётся доступен в библиотеке. Если дело важное — не чистите его
  или держите отдельную копию.
