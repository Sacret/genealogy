# Как работать в этом репозитории

Это генеалогический поиск: в дореволюционных документах, отсканированных
библиотекой Vivaldi (`vivaldi.dspl.ru`), ищутся две фамилии — **Кармазинъ** и
**Могучевъ**, в дореформенном написании. Сканы распознаются Tesseract, кандидаты
проверяются глазами по скану, итог по каждому документу записывается
вердиктом и публикуется журналом на <https://sacret.github.io/genealogy/>.

Подробное устройство конвейера, причины решений и история ошибок — в
`README.md` (большой, читать нужный раздел по оглавлению). План — `ROADMAP.md`.
Этот файл — короткая памятка о том, что агенту нужно знать до первой команды.

Язык проекта — русский: код с комментариями, коммиты, вердикты, ответы
пользователю.

## Окружение

```bash
.venv/bin/python doctor.py     # Python, Pillow, Tesseract, модель rus
.venv/bin/python audit.py      # целостность всей базы, без сети и без записи
.venv/bin/python tests.py      # тесты
```

Звать скрипты через `.venv/bin/python`. CI (`.github/workflows/checks.yml`)
гоняет `doctor.py`, `audit.py`, `compileall` и `tests.py` — после правок кода
или данных прогнать `audit.py` и `tests.py` локально.

Машина — macOS: `sed -i` без суффикса не работает (файлы править через
Python или Edit), а в zsh `set -- $строка` и `for p in "1 2"` не делят строку на
слова — для пачек с аргументами писать bash-обёртку.

## Кто есть кто

Две линии с разной географией, путать нельзя:

- **Могучевы** — станица Кочетовская, 1-й Донской округ; позже Новочеркасск.
- **Кармазины** — слобода Ровеньки, Ровенецкая волость, Таганрогский округ
  (до 1888 г. — Миусский). Кочетовская к ним отношения не имеет.

Однофамильцы без установленного родства — не находки семьи, а записи в
`namesakes.json`. «Кармасин» (через «с») сам не решать — показать пользователю
цитату, страницу и вырезку и ждать решения. «Кармалин» (через «л») — другая
фамилия. «Карамзинъ» с инициалами может быть опечаткой — сверять по скану.

## Данные

| Файл | Что в нём |
|---|---|
| `vol/<префикс>/<сотня>/<id>/` | Том: `meta.json`, `ocr*/`, `quality.json`, `searches.jsonl`, `crops/`. Путь — только через `docstore.doc_dir(id)`, руками не собирать |
| `documents.json` | Каталог и очередь: просмотрены, в работе, очереди по приоритету, отсев с причиной. Пересобирается сам (`find.py`, `run.py`, `catalog.py --rebuild`) |
| `catalog.jsonl`, `catalog.py` | Кэш заголовков библиотеки и правила раскладки по очередям (`SKIP_SERIES`, `KEEP_BY_ID`, `POOR_SCAN`) |
| `persons.json` | Люди семьи (`iNNNN`), биографии, «где искать дальше» |
| `events.jsonl`, `events.py` | События людей (`eNNNN`) с документом, страницей и цитатой. Новая находка с родством — новое событие, иначе `audit.py` не пропустит |
| `namesakes.json`, `namesakes.py` | Однофамильцы (`u-...`) и явные гипотезы о тождестве |
| `places.json` | Улицы, участки, приходы, хутора, фонды ГАРО, кредиторы — с источником. Сначала смотреть сюда, новое о местах дописывать сюда |
| `requests.md` | Нечитаемые на скане полосы для заказа в библиотеке. Если вердикт оговаривает нечитаемое место — дописать строку |
| `dismissed_words.json` | Обычные слова, похожие на основу фамилии |
| `journal.html`, `journal/` | Опубликованный журнал. Собирается сам при каждом `find.py`; руками не править |

Префиксы документов: `bv` (книги), `bx` (приказы, календари, справочники),
`pn` (газеты), `ot`, `pm`, `br`, `bc` — список в `docstore.PREFIXES`. Номера
не идут по порядку серии: следующий документ берётся из очереди в
`documents.json`, а не угадывается по номеру.

Сканы — кэш, а не данные: `fetch.ensure_page` дотягивает выброшенную
страницу, `prune.py --apply` чистит. В git идут только сканы страниц с
подтверждёнными находками (список в `.gitignore` пишет `prune.py`).

## Обработка документа

```bash
.venv/bin/python run.py --next 1 --find Кармазинъ Могучевъ   # или run.py <url> --find ...
.venv/bin/python crop.py <id> <стр> <слово>                   # вырезка для проверки глазами
.venv/bin/python verdict.py draft Кармазинъ <id> ...          # черновик «не найдена»
.venv/bin/python verdict.py accept Кармазинъ <id> --note "..."
.venv/bin/python find.py <id> Могучевъ --status found --pages 223 --verdict "НАЙДЕНА. ..."
.venv/bin/python prune.py <id> --apply
```

Газеты (`pn`) распознаются плохо, и штатного прохода мало: кроме `run.py`
нужны `rescue.py <id> --pages 1-N` и то же с `--cols` (штатно перечитываются
только полосы с оценкой ниже 60) и сплошной проход `stripes.py <id>` —
кандидаты собираются по всем слоям. Подробности — в разделе «Газеты»
`README.md`.

Каждый кандидат проверяется по скану (вырезка или страница), а не по тексту
OCR. Сырое число кандидатов — не результат.

## Правила вердиктов

Часть правил проверяет сам `find.py --verdict` и отказывается писать текст.
Если отказал — исправить текст, а не обходить проверку.

- Вердикт пишется только на `Кармазинъ` и `Могучевъ`, и поиск этих двух
  фамилий должен лежать в журнале. Все вспомогательные поиски (обрывки основы,
  места, другие слова) — с `--no-log`, иначе том в журнале висит «не проверена».
- Проза — современной орфографией, включая имена: «Алексей Могучев». Старое
  написание — только в кавычках как цитата из оттиска.
- Без внутренних идентификаторов `i0023`/`e0016` в тексте: человек по имени,
  событие по сути. Родство привязывается флагами `--kin` и `--person`.
- Без путей к вырезкам (`crops/...png`): журнал сам показывает вырезку по
  `--pages`.
- Другой документ называть голым номером (`pn0024160, стр. 3`) — журнал
  сделает ссылку, а `prune.py` не удержит чужую страницу.
- Число «при расширенном пороге» — из `find.py --loose --no-log` без `--short`.
- Честно оговаривать полноту: какие полосы ниже порога, что прочитано
  выборочно, что не читается.

Находку с возможным родством записать и показать пользователю — признание
родства (`--kin`, событие в `events.jsonl`) решает пользователь.

## Коммиты

- Только когда просит пользователь; пушить — тоже только по просьбе.
- Заголовок по-русски, в повелительном наклонении, по содержанию:
  «Проверить Донские ведомости № 137 и 140 за 1914 год», «Признать родство:
  ...». В теле — что нашлось по Кочетовской и Ровенькам, если нашлось.
- После поисков в коммит идут `documents.json`, `journal.html`, `journal/`,
  изменённые `places.json`/`persons.json`/`events.jsonl` и файлы тома, которые
  не в `.gitignore`. Деплой журнала срабатывает от `journal.html`, `journal/`
  и вырезок.

## Чего не делать

- Не редактировать `journal.html`, `documents.json` и `.gitignore`-список
  сканов руками — их пересобирают скрипты.
- Не удалять тома и вердикты, не переписывать старые вердикты без просьбы.
- Не ставить в очередь заглавия с «история»/«исторический очерк» и про воду
  (реки, порты, лоции) — их отсеивает `SKIP_SERIES`.
- Не гонять тяжёлый опрос каталога с нуля по `pn`: у газет нумерация начинается
  далеко не с нуля, нужен `--range`.
- Временные 404 и зависания сервера Vivaldi бывают — повторить позже, а не
  считать документ пропавшим.
